# Project Agent Instructions

Before development work, read `PROJECT_HANDOFF.md`. It is the official project
handoff and the source of truth for current scope, architecture, completed work,
backend gaps, and the next task.

## Required Handoff Practice

- Follow the development rules and API contract in `PROJECT_HANDOFF.md`.
- Work only on the task requested by the user; do not automatically begin the
  task listed under `Next Task`.
- At the end of a development session, update `PROJECT_HANDOFF.md` to reflect
  verified repository state.
- Preserve its heading order and concise bullet-based style:
  `Project Overview`, `Development Rules`, `API Contract`, `Backend Notes`,
  `Completed Features`, `Remaining Features`, `Current Database Notes`,
  `Mock API Status`, and `Next Task`.
- Move a feature to `Completed Features` only after implementation and
  validation are complete.
- Keep `Remaining Features`, `Mock API Status`, and `Next Task` synchronized
  with the completed work.
- Record backend/database requirements in both the relevant `Backend Notes`
  subsection and `BACKEND_NOTES.md`.
- Never discard or overwrite unrelated user changes when refreshing a handoff.
